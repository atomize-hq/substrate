## Selected A1.3-P0 outcome

A1.3-P0 owns only the preparatory authority-bound transport split required before the later A1.3
packet may resume. Its implementation may either:

1. create a new transport-only launcher for public Start/turn/reattach; or
2. create a mechanically isolated authority-managed branch dedicated to those public callers.

Either option must preserve the existing legacy launcher unchanged for auto-attach and every other
compatibility caller.

`HostSessionAuthority` remains the only durable authority owner. Hidden-owner plan files are
immutable transport projections only. Process spawn, child PID, readiness, timeout, EOF, prompt
delivery, private transport publication, and local adapter errors remain observations only and may
not create, repair, or terminalize startup or post-turn authority truth.

## Exact prohibitions

On the authority-managed public path, A1.3-P0 must not reuse the existing legacy
`launch_hidden_owner_helper` semantics unchanged. It specifically prohibits:

- `wait_for_hidden_owner_helper_readiness`;
- `reconcile_hidden_owner_helper_start_timeout`;
- `stabilize_hidden_owner_helper_start_return`;
- joined readiness or continuity receipt reconstruction;
- legacy `persist_orchestration_session` or `persist_participant` authority writes; and
- any startup or terminal inference derived from readiness, process posture, PID, helper/socket
  state, timeout, EOF, prompt delivery, or local adapter errors.

If the public transport split cannot be implemented inside the named fence without changing
HostSessionAuthority or StateStore schemas, persistence semantics, auto-attach behavior, endpoint
design, receipt/supervisor/member-runtime ownership, or broader lifecycle meaning, the packet must
stop for separate authority.

The implementation may claim A1.3-P0 only if it proves all of the following on Linux:

1. public Start, turn, and explicit reattach use only the newly isolated authority-managed public
   transport path;
2. auto-attach and all compatibility callers remain on the unchanged legacy launcher with no
   `auto_attach.rs` edit or behavior drift;
3. hidden-owner plans remain immutable transport projections, and no plan/process/readiness/local
   observation creates or terminalizes startup or post-turn authority truth;
4. the isolated public path performs no legacy authority writes and no joined readiness/continuity
   reconstruction;

   that startup ownership/post-turn truth still come only from exact protocol evidence, and that
   unchanged caller baselines remain unchanged; and
6. independent read-only review is clean with zero unresolved blocking findings.

Completion of A1.3-P0 does not close A1.3, A1.4, `RG-AUTH-03`, or `RG-BASE-01` by itself. It only
permits the later A1.3 packet to resume under its own separate implementation fence.

- HostSessionAuthority or StateStore schema or persistence-semantics changes;
- general A2 `HostExecutionEpisode` demotion;
- A3 persistence split;
- endpoint redesign;
- receipts, supervisor, or member-runtime work;
- auto-attach producer, eligibility, settlement, or behavior changes;
- macOS, Windows, or Linux R3 reopening; or
- any generated `AGENTS.md` / `CLAUDE.md` change.

shared-surface integration packet for its exact public transport split: it names ownership, freezes

platform work and does not make macOS or Windows proof a blocker for the packet itself.
