## Why A1.3-P0 and A1.3 stay held

The held A1.3-P0 packet correctly proved that the public path still entered the legacy launcher
corridor and that `agent_runtime/auto_attach.rs` remained a separate frozen caller. It does not
remain executable as a standalone prerequisite. The same real public CLI/helper/REPL path that
needs a new authority-managed transport path also owns:

- real `HostSessionAuthority` consumption for public `Start`, `Attach`, and `ResumeOneTurn`;
- exact startup actor-event and post-turn actor-event resolution; and
- the already-defined B1 acceptance-context seam in
  `crates/shell/src/execution/orchestrator_world_dispatch.rs` where transition-scoped retained
  turns can carry exact `host_transition_correlation`.

Separating those duties into a transport-only preparatory packet would either silently reopen the
held A1.3 fence across the same files or force a second non-atomic edit on the same public
consumer path. The historical A1.3 fence therefore also remains held: its old code boundary did
not include the necessary public transport path and did not name the acceptance-context projection
seam. The correction is a new packet, not a silent widening of either held fence.

## Corrected public Start continuity protocol

### Boundary of the Start-continuity correction

The Start-continuity correction is a predecessor to the remaining A1.3-P1 public-adoption work,
not the public-adoption packet itself. It owns public `Start` only. It does **not** own public
`Turn`/`run_turn` adoption and must not route public Turn through HSA or restore legacy StateStore
authority writes. Its complete successor-readiness proof is exactly that Start produces a valid
durable continuation handle and HSA can use that handle to issue and apply the already-existing
`ResumeOneTurn` protocol. The later A1.3-P1 public-adoption work remains responsible for routing
public Turn through that protocol. The broader packet scope below remains future authority and is
not claimed by this correction.

The A1.2 Start application remains honest history and remains the first durable phase: it may
transiently leave authority `ActiveAttached` with startup ownership Pending or Accepted and with no
resume-handle reference. A successful nonterminal public Start must then complete both of these
new additive HSA phases:

1. **EstablishStartContinuation.** Submit the caller's real prompt at most once automatically. When
   that exact wrapper exchange produces authenticated provider-acceptance evidence and a
   backend-native continuation ID, authenticate them against the exact
   authority store, orchestration session, authoritative participant, backend/protocol, Start
   intent, application/run, and applicable authority revision. Persist the corresponding immutable
   handle object and durably reference it from HSA while preserving `ActiveAttached`.
2. **SettleStartTurn.** Consume exact Substrate-owned completion evidence for that same inaugural
   turn, preserve the registered handle, and durably move from `ActiveAttached` to exactly one of
   `ParkedResumable` for clean resumable completion, `AwaitingAttention` when exact canonical
   obligation evidence requires attention, or `Terminal` for exact terminal completion.

Public `Start` must not report success until both phases are committed. It must never send a
synthetic, empty, hidden, bootstrap, warm-up, or substitute prompt. A backend/UAA identifier is an
opaque continuation capability only; it is never posture, ownership, liveness, attention, or
terminal truth. PID, process survival, readiness, helper/socket/endpoint/plan state, timeout, EOF,
prompt delivery alone, local adapter error, compatibility projection, and legacy StateStore
snapshots likewise cannot establish or settle HSA posture.

Crash/retry is exact, at-most-once, and fail closed:

- `PromptNotSubmitted` is the only transaction phase that permits automatic provider submission;
- immediately before provider handoff, persist `PromptSubmissionNoReplayBarrier`. This marker is
  only a no-replay barrier: it is not provider acceptance, a continuation, successful Start, or
  resumable state;
- if execution crashes or otherwise loses the result after that barrier but before authenticated
  provider-acceptance evidence is durably registered, recovery records
  `PromptSubmissionIndeterminate`. Retry exact-joins that unresolved result, performs zero provider
  submissions, and returns `submission_outcome_unknown`; it never reports success or resumption;
- a handle object persisted before HSA registration remains unreferenced and non-authoritative;
  exact retry reuses or reproduces the same commitment and converges;
- registration committed before settlement retains `ActiveAttached` plus the exact handle;
  public Start is not successful and retry must not replay the prompt; and
- settlement committed before the public response is already the successful durable result;
  exact retry joins and returns it without replaying the prompt.

## Mechanical projection definition

Within this packet, **mechanical** means exact projection only:

- copy already HSA-authorized values into the existing
  `acceptance_context.host_transition_correlation` field only through the real retained-turn
  submission seam in `orchestrator_world_dispatch.rs`
  (`prepare_retained_acceptance_submission`, its retained-turn invocation of
  `world_work_acceptance_context`, and
  `build_continue_world_worker_submit_request_with_acceptance_context`);
- add no new durable state;
- make no new semantic choice or inference;
- add no new B1/C1/B3.1 validation or reinterpretation beyond the already documented equality
  checks; and
- do not reinterpret request ID, message ID, active run, readiness, PID, helper/socket/process
  posture, timeout, EOF, or local adapter state as transition truth.

If the public-adoption path requires anything more than that exact projection, the packet must stop
for separate authority instead of inventing a new seam owner.

1. public `Start`, turn, and explicit reattach use only the new authority-managed public transport

2. the real public CLI/helper/REPL path consumes exact A1.2 authority results and resolves startup

   adapter error, or compatibility fallback becomes startup or post-turn semantic truth;
5. legacy helper behavior for compatibility callers and every auto-attach path remains unchanged;
6. the caller's real prompt is submitted at most once automatically with no synthetic prompt; a
   clean successful Start submits that one real prompt, registers its authenticated provider
   handle, and becomes `ParkedResumable`; canonical attention evidence produces
   `AwaitingAttention`, and exact terminal evidence produces `Terminal`;
7. success is impossible without a registered handle; backend ID alone cannot change posture;
   exact stale, duplicate, reordered, wrong-session, wrong-run, substituted, or mismatched evidence
   fails closed; pre-handoff retry can submit once, ambiguous-handoff retry returns the durable
   indeterminate result with zero submissions, and registered/settled retry converges without
   prompt replay;
8. a later `ResumeOneTurn` consumes the handle registered by Start while existing Attach/Resume,
   compatibility, and auto-attach behavior remain green; and
9. independent read-only review is clean with zero unresolved blocking findings.
