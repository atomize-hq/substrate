## Why A1.3-P0 and A1.3 stay held

The held A1.3-P0 packet correctly proved that the public path still entered the legacy launcher
corridor and that `agent_runtime/auto_attach.rs` remained a separate frozen caller. It does not
remain executable as a standalone prerequisite. The same real public CLI/helper/REPL path that
needs a new authority-managed transport path also owns:

- real `HostSessionAuthority` consumption for public `Start`, `Attach`, and `ResumeOneTurn`;
- exact startup actor-event and post-turn actor-event resolution; and
- the already-defined B1 acceptance-context seam where transition-scoped retained turns can carry
  exact `host_transition_correlation`.

Separating those duties into a transport-only preparatory packet would either silently reopen the
held A1.3 fence across the same files or force a second non-atomic edit on the same public
consumer path. The historical A1.3 fence therefore also remains held: its old code boundary did
not include the necessary public transport path and did not name the acceptance-context projection
seam. The correction is a new packet, not a silent widening of either held fence.

## Selected A1.3-P1 outcome

A1.3-P1 is one coherent future public-adoption packet. In one bounded implementation it must:

1. create the new authority-managed public transport path for public `Start`, turn, and explicit
   reattach without changing legacy helper behavior for compatibility callers;
2. consume the already-landed A1.2 authority on the real public CLI/helper/REPL path, including
   exact startup actor-event resolution and exact post-turn resolution; and
3. mechanically project already HSA-authorized `host_transition_correlation` into the existing B1
   acceptance-context seam for transition-scoped retained world turns.

`HostSessionAuthority` remains the sole durable semantic owner. `HostExecutionEpisode`,
`HiddenOwnerHelperLaunchPlan`, and the public transport path remain observation or transport only.
B1/B2.1/B3.1/C1 keep their existing semantics and ownership.

## Mechanical projection definition

Within this packet, **mechanical** means exact projection only:

- copy already HSA-authorized values into the existing
  `acceptance_context.host_transition_correlation` field on the real retained-turn submission path;
- add no new durable state;
- make no new semantic choice or inference;
- add no new B1/C1/B3.1 validation or reinterpretation beyond the already documented equality
  checks; and
- do not reinterpret request ID, message ID, active run, readiness, PID, helper/socket/process
  posture, timeout, EOF, or local adapter state as transition truth.

If the public-adoption path requires anything more than that exact projection, the packet must stop
for separate authority instead of inventing a new seam owner.

1. public `Start`, turn, and explicit reattach use only the new authority-managed public transport

2. the real public CLI/helper/REPL path consumes exact A1.2 authority results and resolves startup
   and post-turn truth only from exact actor-bound protocol evidence;

5. legacy helper behavior for compatibility callers and every auto-attach path remains unchanged;
   and
6. independent read-only review is clean with zero unresolved blocking findings.

Completion of A1.3-P1 may close the real public-adoption wall and `RG-BASE-01` when its exact
proof passes. It does **not** close A1.4, A1 as a whole, macOS parity, Windows, or R3.
