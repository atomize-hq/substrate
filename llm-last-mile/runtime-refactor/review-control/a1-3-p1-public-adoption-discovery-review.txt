VERDICT: FINDINGS

- `A13P1-P2-001` — P2: Linux HSA Attach still activates forbidden legacy StateStore authority writes. `async_repl.rs:5955` routes authority-managed Attach through `start_control_only_attach_runtime`; that function marks the legacy manifest/session Ready/Active and calls `persist_runtime_snapshots` at `async_repl.rs:7812-7839`, then continues persisting heartbeats at `async_repl.rs:7852-7883`. `persist_runtime_snapshots` invokes both legacy `persist_orchestration_session` and `persist_participant` (`control.rs:2179-2188`). HSA ownership acceptance is submitted only afterward at `async_repl.rs:5969-5972`, so legacy persistence success gates the adopted authority path. This violates the explicit StateStore-write exclusion and sole-HSA authority boundary. Add an authority-managed control-only Attach branch that suppresses these legacy authority writes and derives completion solely from the typed target-actor protocol event; if a compatibility projection is still necessary, it requires an authorized post-HSA projection rather than these legacy writers.

- `A13P1-P2-002` — P2: Exact ResumeOneTurn terminal failure evidence never terminalizes HSA. The event loop recognizes an exact `turn.failed`/`result.error` lifecycle sequence, but at `async_repl.rs:6505-6511` only latches an error; only the successful branch calls `settle_authority_managed_resume_post_turn` at `async_repl.rs:6513-6527`. Since input was already durably accepted at `async_repl.rs:5982-5994`, authority remains `ActiveAttached` with post-turn `Pending`, and retries are permanently rejected as `submission_outcome_unknown` at `agents_cmd.rs:1016-1019`. This fails the required exact-terminal-evidence-to-`Terminal` behavior and retry convergence. Submit/join the existing HSA `TerminalFailure` post-turn protocol using the authenticated correlation and `TargetFailedAfterInputAcceptance` evidence instead of inventing new semantics.

- `A13P1-P2-003` — P2: A completed Attach can be reused to spawn another helper while reusing the prior actor evidence. `current_applied_public_successor` accepts any current applied Attach without checking whether `startup_ownership` is still pending (`agents_cmd.rs:2280-2333`), and the builder reuses it at `agents_cmd.rs:2361-2370`. The launcher then unconditionally spawns another helper (`control.rs:579-615`), while the waiter immediately treats the previously committed `Accepted` state as completion (`control.rs:713-718`). Thus a later public reattach bypasses HSA’s `ActiveAttached` issuance rejection and can return using stale episode evidence. This contradicts the duplicate-launch rejection asserted at `agent_public_control_surface_v1.rs:3774-3787` and the exact-duplicate requirement. Restrict recovery joins to genuinely in-flight startup ownership with durable request identity; completed Attach must reject or return its prior result without spawning.

- `A13P1-P2-004` — P2: The required Linux test gate contains a deterministic candidate-only failure and lacks successful public ResumeOneTurn/correlation proof. `public_same_session_parked_status_turn_reattach_and_stop_stay_on_one_orchestration_session_id` creates only legacy parked StateStore records and expects Linux turn success (`agent_public_control_surface_v1.rs:4719-4760`), but Linux `run_turn` necessarily rejects that detached host at `agents_cmd.rs:1175-1185` because no HSA authority exists. Meanwhile the new Linux HSA turn case explicitly expects post-turn failure and leaves HSA pending (`agent_public_control_surface_v1.rs:2681-2833`); it never proves the production retained correlation/ledger cut reaches successful public settlement. The reported `--no-run` gate cannot expose either issue. Rewrite or platform-gate the legacy-only scenario and add an authorized Linux integration case using real Start, production retained acceptance-context projection, authenticated terminal cut, and successful HSA settlement.

The review was read-only and made no repository changes.
