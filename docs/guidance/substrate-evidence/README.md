## Full cleanup plan and holds

All allocations in historical records are point-in-time measurements, not current reclaim. Nested rows are nonadditive; hardlinks, live processes, mount boundaries, unique inputs and protected references can reduce reclaim. The audit's approximately 47 GiB canonical-debug historical ceiling is not a current safe-reclaim or capacity promise. The continuation action removed the remaining frozen canonical `target/debug` descendants and the root; the root was absent at postcheck and can be recreated by a later build:

1. **B1** compiler incremental files were removed across the initial and continuation actions, including the remaining locks and internal hardlinks.
2. **B2** selected debug library archives and metadata were removed in the initial action; the remaining frozen debug outputs and root were removed in the continuation action. The [continuation receipt](cleanup-receipt-canonical-debug-continuation.json) records both the allocated-byte estimate and the observed filesystem change.
3. **B3** selected integration debug outputs were removed; the debug root and 517 held entries, including the frozen actor, its aliases and pinned dependencies, remain. The [integration debug receipt](cleanup-receipt-integration-debug.json) records actual allocated bytes, separate filesystem observations and remaining holds. Publication and remote readback of this receipt update are pending.
4. **B4** isolated inventory target: retain private original proof and source until selected and preserved.
5. **B5** comparison roots: preserve each base/head source and original results; GitHub custody remains unverified.
6. **B6** other repository and worktree candidates: preserve each remaining repository's exact source, changes, inputs and selected records, check ownership and remote restoration, and never infer eligibility from age or directory name.
7. **B7** mixed, loose and temporary roots: classify source, results, private configuration, caches and unrelated repositories before any separate disposition. Preserve shared Cargo state, installed files, backups and rollback dependencies. Runtime/session records and protected workflow trees remain local and are not publication payloads.

The [integration target continuation receipt](cleanup-receipt-integration-target-continuation.json) records the separately completed release compiler-output and Lift check-cache cleanup, its actual accounting and remaining holds. Publication and remote readback of this receipt update remain pending. The prior integration debug action remains separately accounted.

Four historical lock hashes and two Git metadata probes were unavailable in the accepted audit; affected source groups remain held until resolved. Historical R2 command, cwd/time or outcome metadata is incomplete where the manifest says so. Other original results and private custody remain unselected for many groups. Missing original binary history alone does not prevent eligible cleanup, but a rebuilt artifact is not an original result. Do not remove a path or ancestor containing a protected dependency. Do not use `cargo clean`, `git clean` or pruning. A dirty worktree may be removed with an exact reviewed `git worktree remove --force` command only after its complete source and record preservation and the applicable checks are established. Full audit and subsequent batches are future work, not permission for this increment.
